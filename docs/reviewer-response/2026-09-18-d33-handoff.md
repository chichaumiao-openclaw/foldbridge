## 当前实现：可保留的检查与待复核规则

保留严格检查：

- model/label/auth/insertion/component 身份必须有明确证据；显式冲突不能被补全覆盖。
- same-author-chain 的额外 polymer 坐标仍触发 coverage failure；不可通过删除检查“修好”。
- 不完整 mmCIF loop 保留失败，不能静默删除 anisotrop category。
- malformed 输入不是已验证的结构性 `not_computable`。
- DSSR 精确 `no nucleotides found` 仅在核实 P-only 核酸结构等既定证据后进入不可计算分类。
- 非目标同作者链 ligand 不能获得可点击的目标 residue 导航。

候选规则仍需复核：

- `canonicalByAtomIdentity` 用 `_struct_asym`、`_entity_poly`、`_entity_poly_seq` 与 atom entity/position 建立结构 canonical 证据。
- DSSR `PSU` 的真实 `nt_code=P` 不是 canonical base。已有真实证据与回归反例；不能将 P 猜成 canonical 碱基。
- 当前代码将 `compId=N` 的 expected canonical 设置为 `residueBase`（来自 `parentBase`）。**这是未厘清来源的候选，不应直接推广到全量。**
- metadata 缺失时使用 DSSR canonical code 的分支、metadata 存在但不完整时的处理，都需形成明确契约，不能成为隐式 fallback。
- DSSR 三字符 component 前缀匹配仅是候选，须核实 v1.9.10 行为和同 locus 冲突，不能任意前缀匹配。
- 非目标蛋白 VAL/SER 微异质已找到实例，目标 RNA/DSSR 身份仍必须唯一；真实整 Case 验收未完成。
